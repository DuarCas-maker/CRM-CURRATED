# Escenarios críticos

1. Dos tareas abiertas y una completada en el mismo expediente producen Tareas2; las dos abiertas P1 producen P1=2. Repetir un ID no duplica el conteo. El responsable es el de cada tarea.
2. Un asesor autorizado con cero carga sigue visible; el nombre Alejandro no activa ninguna exclusión. Un seller no obtiene casos o métricas ajenas por cambiar owner.
3. Una firma de aplicación no cambia el caso a Funded/contrato firmado. Proceso histórico inactivo no sustituye el vigente. Oferta de mayor monto y oferta elegida siguen distintas.
4. Más de50 casos, mensajes duplicados, múltiples ofertas y cambios de página no alteran los totales globales. Orden estable para empates.
5. Una respuesta en otro hilo, un draft, un fallo de envío, una respuesta anterior o de fecha inválida no resuelve una oferta pendiente.
6. Eventos sin fecha o evidencia no se cuentan en gráficas diarias; zona horaria del servidor no cambia el día del modelo. Sin acceso financiero se reciben nulos, nunca importes ocultos mediante CSS.
7. Las seis pestañas conservan búsqueda/asesor y permiten abrir el contexto autorizado. El control de pestañas funciona con teclado; la tabla ancha tiene scroll local a360px.
8. Error de API, cambio rápido de filtros y respuesta antigua no muestran datos de otro filtro como si fueran actuales. Demo funciona con registros ficticios y ninguna llamada externa.
