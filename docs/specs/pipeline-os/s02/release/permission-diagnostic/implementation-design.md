## Decisiones de implementación

- Scope congelado y derivado de la instantánea/referencia:30 relaciones ACL,206 identidades funcionales,70 funciones ACL más7 controles046/047, ocho policies/tres vistas y93 relaciones para metadata de columnas/constraints. Las firmas se identifican por tipos internos calificados del catálogo, no por to_regprocedure con search_path permisivo. Hash SHA256 del scope embebido en la salida.
- SQL generado desde plantilla pública y scope estáticos revisables; BEGIN READ ONLY, search_path=pg_catalog, timeout15s/lock2s, un SELECT de metadata y ROLLBACK. No agrega transporte/ejecutor remoto. Ante exceso de cardinalidad la salida no incluye datos parciales silenciosos: completeness=false. Límite2MiB de salida/entrada y límites por sección; el comparador falla cerrado ante duplicados, objeto faltante, contexto erróneo, columnas desconocidas o exceso de límites.
- Los nombres de roles no estándar se exportan como `role_`+MD5 del nombre, nunca nombres potencialmente personales. La función/campo que se inspecciona no se invoca; cuerpos/defaults/configuración se hashean, sin imprimirlos. Se exponen únicamente clases de search_path, no valores arbitrarios. No leer tablas de negocio ni auth.users/pg_authid. Metadata FK hacia auth.users sí se permite, sin filas.
- pg_has_role con MEMBER/USAGE permite distinguir membresía de herencia efectiva usando API compatiblePG15. Las aristas básicas no usan campos añadidos en16; recorrer con profundidad máxima8 y detectar límite antes de clasificar. Defaults actuales no prueban cuándo se concedió una ACL existente.
- El comparador solo produce hechos/diferencias por objeto y campos, sin valor bruto de entradas inválidas. ACL distintas siguen siendo desvíos aunque las explique un default. Las huellas de formato nunca anulan diferencias de cuerpo/literales/configuración/ACL. Sin resultado de referencia compatible, el estado queda incompleto; nunca aprueba publicación.
- Los ensayos son nuevos y exclusivos de PD. PGlite18 comprueba ejecución/salida/negativos; no se presenta como una instanciaPostgreSQL15 independiente. La compatibilidadPG15 se limita a revisión de catálogos y sintaxis común hasta ejecutarse en un motor15 desechable. No instalar/arrancar infraestructura ni usar producción para resolver ese gate.

Pruebas requeridas: script reproducible, transacción sin mutación, repetición estable, límites y output privado, ACL directa/PUBLIC/heredada/owner/default, fixtures de search_path/CRLF/literal distinto, FK/Storage/policies/vistas, datos faltantes/maliciosos/duplicados y API de CLI sin execute ni env. El contrato READ ONLY y estos escenarios no reabren pilotos de correo.
