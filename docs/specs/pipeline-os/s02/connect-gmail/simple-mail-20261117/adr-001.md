# ADR-001 — Gmail principal y respaldo Composio antes de emisión

2026-11-17. Decisión de producto confirmada por respuestas 8/11/12; diseño técnico propuesto.

El usuario pide una conexión simple y ambos proveedores. La previsión de diez cuentas con 500–700 salidas diarias por cuenta hace preferible Gmail directo como principal. Composio queda disponible dentro de cupo gratuito y como respaldo de un fallo específico de la conexión directa. Google sigue siendo el proveedor del mismo buzón en ambos caminos.

Se elige una fachada de onboarding que automatiza revisiones internas conservando sus garantías, estado por proveedor y fallback durable de un solo mensaje. No se cambia globalmente toda la cuenta de proveedor al fallar una operación. El diseño reutiliza el dispatch, outbox, admission de marca y conciliación existentes.

No se elige catch/reintento por Composio para cualquier excepción: Gmail no ofrece idempotencia de envío y un timeout puede ocultar aceptación. Tampoco se elige duplicar sincronización ni usar Composio para saltar cuotas, bloqueos, pausas o revocaciones. Desactivar validaciones de identidad/permisos para reducir pantallas incumple el alcance.

Consecuencias: dos conexiones requieren dos consentimientos si se quieren ambas autorizadas; una no autoriza la otra. El respaldo gratuito tiene disponibilidad limitada y no es una garantía de continuidad. Un estado incierto requiere conciliación, no reenvío automático. Configurar OAuth y presupuesto es tarea administrativa interna, no trabajo repetido por buzón. La UI debe mostrar degradación real sin exigir comprender tickets/revisiones.

Esta decisión reemplaza para el nuevo flujo la separación manual alta/marca/candidato/comprobación/activación de ADR anteriores; no elimina esas validaciones del backend ni modifica retrospectivamente sus recibos. El rollout debe conservar cuentas conectadas, Gmail legacy y datos históricos.
