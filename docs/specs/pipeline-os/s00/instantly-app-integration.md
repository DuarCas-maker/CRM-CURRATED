## IA-ADR01: extracción pura y Supabase por compare-and-swap

Extraer lógica C de validación/auth/payload/recibos a `src/lib/server/instantly/receiver.ts`, sin imports de Next, filesystem, scripts, env o cliente de red al importar. Wrapper S00 conserva exports/tipos y traduce códigos a S00RunError; mantiene backend de archivos, runner/counter actual sin cambios. La entrada de producción no incorpora scripts/CLI ni .local en la imagen.

Ruta propuesta `src/app/api/integrations/instantly/webhook/[nonce]/route.ts`, runtime nodejs. Flag `INSTANTLY_WEBHOOK_ENABLED=false`; nuevas variables privadas runtime web: INSTANTLY_S00_WEBHOOK_SECRET y INSTANTLY_S00_WEBHOOK_DEDUP_KEY; Supabase/APP_ORIGIN ya existentes. No valores reales o cambios Coolify aquí. Para proxy HTTPS, validar pathname/nonce y construir Request canónico desde APP_ORIGIN validado, ignorando X-Forwarded-Host/Proto no confiables. Callback no exige cookie de navegador/checkOrigin; exige secreto y manifiesto. Control administrativo separado sí exige sesión/MFA/superadmin/checkOrigin. Respuestas externas sin mensajes DB/headers/URL/cuerpos.

Tablas aditivas `instantly_webhook_trials` y `instantly_webhook_receipts`: nonce único, manifiesto C sin secretos, hash de manifiesto, workspace/campaign externos como UUID de proveedor, revision, armado/cierre; recibos ordinal1–16 con hashes HMAC, fecha, contexto/clasificación/duplicado. No FKs falsas hacia campaigns CRM, raw payload o datos de lead. RLS en ambas; revocar acceso directo incluido service_role, conceder solo RPC backend SECURITY DEFINER/search_path vacío.

RPC prepare registra manifiesto inmutable y no arma. RPC read devuelve contexto/estado mínimo. RPC CAS bloquea fila, comprueba revision y valida transición completa/prefijo inmutable y recibo nuevo, almacena atómicamente y avanza revision. Puerto CReceiptStore.transact se conserva mediante CAS con **un único reintento de conflicto**, nunca lecturas/updates desprotegidos. Errores de red/DB no se reintentan automáticamente; no replay ciego de mutaciones. Adaptador RPC acota timeout8s; ninguna aceptación HTTP precede commit. Estado nulo significa preparado sin armar; cierre terminal no permite reabrir. Se usan restricciones SQL además de validación JS.

Control `api/integrations/instantly/trials/[nonce]`: GET estado sanitizado; POST `{action:prepare,manifest,workspace,campaign}` o `{action:arm|close}`. No UI nueva, envío o activación del proveedor. Preparación/armado exigen flags/manifiesto y claves dedicadas coherentes; ningún permiso se deriva del body. Se reutilizan requireUser/checkOrigin/serviceClient actuales mediante adaptadores testeables. El backend DB de C se expone como factory inyectable para futuras pruebas; el CLI S00 permanece con archivos y no se conmuta silenciosamente al nuevo backend.

Alternativa descartada: volumen local compartido con la CLI de este computador; requeriría trasladar ejecución/journal y gestionar persistencia adicional. ## Rollout, riesgos y rollback

Hoy: solo archivos y PGlite descartable. Futuro: migración revisada/autorizada en instancia existente → despliegue autorizado con flagfalse → manifiesto/control/secretos/logging y TLS comprobados → permiso específico de prueba → activación acotada. No ejecutar estas etapas por crear el código. Código nuevo contempla schema ausente como indisponible, nunca fallback a memoria. La ruta/handler por sí solos no prueban el proxy o TLS de Coolify.

Riesgos: el transporte DB/app añade peticiones y latencia. **19/62 del C actual no autoriza tráfico nuevo a la app/Supabase**; antes de la prueba integrada se debe definir/adaptar el control del ensayo y su presupuesto completo, manteniendo43 y sin sustituir el journal por una copia remota. No prometer cargos cero por mocks. Límite16 conserva duplicados como metadatos, solo primera observación es hecho técnico; no hay hechos comerciales.

Rollback remoto propuesto: deshabilitar flag y conservar tablas/evidencia; no borrar recibos ni restaurar contador. Reversa destructiva solo se prueba sobre PGlite descartable, sin archivo de ejecución remota automática. No backups ni migraciones remotas en este incremento. Rollback de código mantiene wrapper/contratos antiguos y fuente43; no revertir archivos ajenos.
